# WePlanGo — โครงสร้างระบบ MVP

> เอกสารย้อนหลังของ MVP แบบกลุ่ม ดู [WORKSPACE.md](WORKSPACE.md) สำหรับกติกาและข้อมูลระบบห้องทริปรุ่นใหม่

## เป้าหมาย

ช่วยเพื่อนตกลง **ใครถูกชวน ไปวันไหน ไปที่ไหน และใครยืนยันว่าจะไป** โดยทุกคนเห็นคำตอบล่าสุดตรงกันบนมือถือ เส้นทางหลักคือสร้างทริป → ชวนเพื่อน → เสนอตัวเลือก → โหวต → ผู้จัดยืนยัน → เพื่อนตอบรับ

MVP ครอบคลุมกลุ่มและทริป, ลิงก์เชิญ, โหวตวันและสถานที่, ผลรวม, นัดหมายที่ยืนยัน, RSVP, รายการแจ้งเตือนในเว็บ และข้อความสำหรับคัดลอกไปส่งในแชต ส่วนแชตในแอป, หารค่าใช้จ่าย, รูปภาพ, แผนที่แบบฝัง, ปฏิทินกิจกรรมละเอียด และอีเมลแจ้งเตือนอยู่หลัง MVP

## เทคโนโลยีและการรัน

| ชั้น | ทางเลือก MVP | เหตุผล |
| --- | --- | --- |
| เว็บ | Next.js App Router + TypeScript | หน้าเว็บมือถือและคำสั่งฝั่งเซิร์ฟเวอร์อยู่ในโปรเจกต์เดียว |
| บัญชี | Supabase Auth, Google OAuth | เพื่อนทั่วไปเข้าใช้ได้โดยไม่ต้องตั้งบริการส่งอีเมลสมัครสมาชิก |
| ข้อมูล | Supabase PostgreSQL + SQL migrations | ความสัมพันธ์และข้อบังคับของคะแนน/สมาชิกตรวจได้ในฐานข้อมูล |
| สิทธิ์ | Server-side checks + PostgreSQL RLS | ป้องกันการเปิด URL หรือเรียกคำสั่งตรงโดยคนนอก |
| โฮสต์เมื่อทดลอง | Vercel Hobby + Supabase Free | เริ่มด้วยค่าบริการ 0 บาทสำหรับการทดลองส่วนตัวที่ไม่ใช้เชิงพาณิชย์ |

Vercel Hobby จำกัดการใช้ส่วนตัวที่ไม่ใช่เชิงพาณิชย์ และ Supabase Free มีโควตาพร้อมความเป็นไปได้ที่โปรเจกต์ถูกพักเมื่อไม่ค่อยมีการใช้งาน จึงยังไม่ถือเป็นสภาพแวดล้อมที่รับประกันความพร้อมใช้งานตลอดเวลา ใช้โดเมน `.vercel.app` ก่อน ไม่ซื้อโดเมนใน MVP

ข้อจำกัดของบริการฟรีอาจเปลี่ยนได้ ให้ตรวจ [ราคา Supabase](https://supabase.com/pricing), [การพักโปรเจกต์ฟรี](https://supabase.com/docs/guides/platform/free-project-pausing) และ [เงื่อนไข Vercel Hobby](https://vercel.com/docs/plans/hobby) อีกครั้งก่อน deploy

หน้าอ่านข้อมูลใช้ Server Components; การเปลี่ยนข้อมูลใช้ Server Actions หรือ Route Handlers ที่เรียก service เดียวกัน ทุกคำสั่งตรวจตัวตน สิทธิ์ และสถานะทริปซ้ำฝั่งเซิร์ฟเวอร์ ไม่ใช้ service-role key ในเบราว์เซอร์ การยืนยันผลและรีเซ็ต RSVP ทำในธุรกรรมเดียว ฐานข้อมูลเปลี่ยนผ่าน SQL migrations เท่านั้น

## โครงสร้างโค้ดที่ตั้งใจสร้าง

```text
src/
├── app/                  # หน้าเว็บ, auth callback, Server Actions/Route Handlers
├── components/           # ส่วนแสดงผลที่ใช้ร่วมกัน
├── features/
│   ├── access/           # สิทธิ์กลุ่ม/ทริปและลิงก์เชิญ
│   ├── groups/           # กลุ่มและสมาชิก
│   ├── trips/            # ทริป ผู้ถูกชวน สถานะ และแผนที่ยืนยัน
│   ├── voting/           # ตัวเลือก คำตอบ และผลรวม
│   └── notifications/    # กิจกรรมและแจ้งเตือนในเว็บ
└── lib/                  # Supabase client, validation, เวลา และข้อผิดพลาดร่วม
supabase/
├── migrations/           # schema, constraints, RLS, database functions
└── tests/                # ทดสอบนโยบายสิทธิ์ฐานข้อมูล
docs/features/             # สเปกพฤติกรรมรายฟีเจอร์
```

## หน้าและทางเข้าหลัก

| URL | หน้าที่ |
| --- | --- |
| `/` | อธิบายการใช้งานและเข้าสู่ระบบ |
| `/auth/callback` | รับผล Google OAuth และกลับไปยัง URL ที่ผู้ใช้เปิดไว้ |
| `/groups` | กลุ่มของฉันและทริปที่ต้องตอบ |
| `/groups/[groupId]` | สมาชิกกลุ่มและทริปของกลุ่ม |
| `/groups/[groupId]/settings` | ข้อมูลกลุ่ม สมาชิก และลิงก์เชิญ |
| `/groups/[groupId]/trips/new` | สร้างทริปแบบร่าง |
| `/trips/[tripId]` | ตัวเลือก ผลโหวต แผนยืนยัน และ RSVP ตามสถานะ |
| `/invite/[token]` | ตรวจลิงก์ แสดงชื่อกลุ่ม/ทริป และให้กดเข้าร่วม |
| `/notifications` | การเปลี่ยนแปลงที่เกี่ยวข้องกับผู้ใช้ |

## ข้อมูลหลัก

| ตาราง | ข้อมูลและข้อบังคับสำคัญ |
| --- | --- |
| `profiles` | `user_id` อ้างถึง Supabase Auth, ชื่อที่แสดง, รูป |
| `groups`, `group_members` | ผู้ดูแล/สมาชิก; คู่ `group_id,user_id` ไม่ซ้ำ |
| `invite_links` | กลุ่ม, `trip_id` ที่อาจว่าง, แฮชโทเคน, ผู้สร้าง, วันหมดอายุ, วันเพิกถอน; ลิงก์ทริปพาเข้ากลุ่มและทริป |
| `trips` | กลุ่ม, ผู้จัด, ชื่อ, รายละเอียด, สถานะ, กำหนดปิดโหวต, เขตเวลา, ตัวเลือกที่ยืนยัน, `plan_version`, จุด/เวลานัดพบ |
| `trip_participants` | คนที่ถูกชวนเฉพาะทริป, สถานะคำเชิญ `pending/interested/declined`; คู่ `trip_id,user_id` ไม่ซ้ำ |
| `date_options`, `place_options` | วันเริ่ม/สิ้นสุด หรือชื่อ/ที่อยู่/ลิงก์แผนที่ พร้อมผู้เสนอและทริปเจ้าของ |
| `date_votes`, `place_votes` | คำตอบหนึ่งคนต่อหนึ่งตัวเลือก; เก็บเวลาที่แก้ล่าสุด |
| `vote_submissions` | เวลาที่ผู้ร่วมทริปกดส่งคำตอบวันและสถานที่ เพื่อแยก “ยังไม่ตอบ” ออกจาก “ไม่เลือกสถานที่ใด” |
| `trip_rsvps` | คำตอบ `going/maybe/not_going` พร้อม `plan_version`; คู่ `trip_id,user_id,plan_version` ไม่ซ้ำ |
| `trip_events`, `notification_reads` | ประวัติการเปลี่ยนแปลงสำคัญและสถานะอ่านแจ้งเตือนของแต่ละคน |

เก็บเวลาเป็น UTC และแสดงตาม IANA timezone ของทริป (`Asia/Bangkok` เป็นค่าเริ่มต้น) ตัวเลือกที่ยืนยันต้องเป็นของทริปเดียวกัน ตรวจทั้งในคำสั่งและฐานข้อมูล ผลโหวตนับเฉพาะผู้ร่วมทริปปัจจุบันที่ไม่ปฏิเสธคำเชิญ

## สถานะและกติกาที่มีผลทั่วระบบ

```text
draft → voting → confirmed → completed
  ↘ cancelled  ↘ cancelled  ↘ cancelled
```

- `draft`: ผู้จัดและผู้ร่วมทริปที่ถูกชวนเสนอตัวเลือกได้ ผู้จัดแก้และลบตัวเลือกได้
- `voting`: ชุดตัวเลือกถูกล็อก ผู้ร่วมทริปโหวตและแก้คำตอบของตนก่อน `vote_deadline` ได้
- เมื่อเลยกำหนด ระบบปฏิเสธคะแนนใหม่ทันทีและหน้าเว็บแสดง “รอผู้จัดสรุป” แม้สถานะในฐานข้อมูลยังเป็น `voting`; ไม่ต้องรอ cron จึงปิดโหวตได้ถูกต้อง
- `confirmed`: ผู้จัดเลือกหนึ่งวันและหนึ่งสถานที่ เพิ่มเวลาหรือจุดนัดพบ แล้วผู้ร่วมทริปตอบ RSVP ได้
- `completed` และ `cancelled`: ผู้จัดเปลี่ยนสถานะได้; ทริปที่ยกเลิกแสดงเหตุผลถ้ามี
- การเปลี่ยนวัน สถานที่ หรือข้อมูลนัดพบที่มีผลต่อการเดินทางหลังยืนยันจะเพิ่ม `plan_version`; RSVP ของรุ่นก่อนยังเก็บเป็นประวัติแต่ไม่แสดงเป็นคำตอบปัจจุบัน

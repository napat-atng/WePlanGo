# WePlanGo — แผนสร้าง MVP

> แผนย้อนหลังของ MVP แบบกลุ่ม ดู [WORKSPACE.md](WORKSPACE.md) สำหรับการพัฒนาระบบห้องทริปรุ่นใหม่และรายการตรวจรับปัจจุบัน

เป้าหมายของแผนนี้คือให้สองบัญชี Google ต่างกันสร้างทริป ชวนกัน โหวต ยืนยัน และตอบรับได้ครบผ่านเว็บมือถือ โดยใช้บริการระดับฟรีสำหรับการทดลองส่วนตัว แต่ละช่วงทำเป็นงานแนวตั้งที่เปิดใช้งานและตรวจได้จริง

## 0. ตั้งฐานโปรเจกต์

1. สร้าง Next.js App Router + TypeScript พร้อมหน้าเริ่มต้นที่อ่านบนมือถือได้ และจัดโครง `src/features/` ตาม [STRUCTURE.md](STRUCTURE.md)
2. ตั้ง Supabase project, Google OAuth, callback URL สำหรับ local และโดเมนทดลอง; เก็บ secret ใน environment เท่านั้น
3. สร้าง SQL migrations สำหรับตารางหลัก ข้อบังคับ `unique`/FK/check, indexes ของทริปและคะแนน และ RLS ของทุกตารางที่เปิด API
4. สร้าง Supabase client ฝั่งเซิร์ฟเวอร์และเบราว์เซอร์, helper ตรวจตัวตน/สมาชิก/ผู้จัด และหน้า error/empty/loading พื้นฐาน

**ผ่านช่วงนี้เมื่อ:** เข้าระบบด้วย Google ได้ทั้งสองบัญชี; ผู้ไม่ได้ล็อกอินถูกส่งไปหน้าเข้าระบบและกลับ URL เดิม; migration และ RLS tests ผ่านในฐานข้อมูล local

## 1. กลุ่ม สมาชิก และลิงก์เชิญ

1. สร้างกลุ่ม ดูกลุ่มของฉัน และจัดการสมาชิกตามบทบาท admin/member
2. สร้าง/เพิกถอนลิงก์เชิญกลุ่มและทริป เก็บเฉพาะแฮชโทเคน แสดงตัวอย่างสิ่งที่จะเข้าร่วมก่อนกดยืนยัน
3. เพิ่มผู้ถูกชวนเฉพาะทริปจากสมาชิกกลุ่ม; ผู้ใช้ภายนอกที่รับลิงก์ทริปจะเป็นสมาชิกกลุ่มและผู้ร่วมทริปในคำสั่งเดียว

**ผ่านช่วงนี้เมื่อ:** A ชวน B ด้วยลิงก์, B เข้าร่วมได้, เปิดลิงก์ซ้ำไม่สร้างสมาชิกซ้ำ, ลิงก์หมดอายุ/เพิกถอนใช้ไม่ได้ และ C ที่ไม่ได้เข้าร่วมเปิดข้อมูลภายในไม่ได้

## 2. ทริป ตัวเลือก และโหวต

1. สร้างทริป `draft` และกำหนดผู้ถูกชวน, ช่วงเวลาโหวต, timezone, วัน/สถานที่เสนอ
2. เปิดโหวตโดยล็อกชุดตัวเลือก; ให้ผู้ร่วมทริปตอบวัน `available/maybe/unavailable` ทุกตัวเลือก และเลือกสถานที่ได้หลายแห่งหรือกด “ไม่มีที่ที่เลือก”
3. บันทึกเวลาส่งคำตอบแต่ละประเภท, แสดงผู้ที่ยังไม่ตอบ, ยอด `available` และ `maybe` แยกกัน และคะแนนสถานที่
4. ตรวจสิทธิ์และ `vote_deadline` ขณะบันทึกทุกครั้ง; หลังหมดเวลาแสดง “รอผู้จัดสรุป”

**ผ่านช่วงนี้เมื่อ:** สองคนโหวตและแก้คำตอบได้ก่อนกำหนด; จำนวนผู้ตอบไม่รวมผู้ปฏิเสธคำเชิญ; เพิ่มตัวเลือกหลังเปิดโหวตไม่ได้; คำสั่งโหวตหลังหมดเวลาถูกปฏิเสธแม้หน้าเดิมยังเปิดอยู่

## 3. ยืนยันแผนและ RSVP

1. หน้าให้ผู้จัดเปรียบเทียบวันจากจำนวนคนว่าง แล้วแสดงคะแนนสถานที่ของกลุ่มคนที่ว่างในวันที่เลือก พร้อมเตือนเมื่อคู่วัน/สถานที่มีคนรองรับน้อย
2. ยืนยันวัน สถานที่ เวลาและจุดนัดพบในธุรกรรมเดียว โดยตรวจสิทธิ์ สถานะ กำหนดเวลา และความเป็นเจ้าของตัวเลือกซ้ำ
3. ให้ผู้ร่วมทริปตอบ `going/maybe/not_going`; แสดงรายชื่อผู้ไปตามแผนรุ่นปัจจุบัน
4. หากผู้จัดเปลี่ยนข้อมูลสำคัญหลังยืนยัน ให้เพิ่ม `plan_version`, เก็บ RSVP เดิมเป็นประวัติ และแสดงทุกคนว่าต้องตอบใหม่

**ผ่านช่วงนี้เมื่อ:** ยืนยันตัวเลือกจากอีกทริปไม่ได้; คนสองคนตอบ RSVP แยกกันได้; เปลี่ยนแผนแล้วรายชื่อผู้ไปเดิมไม่ถูกนับเป็นคำตอบปัจจุบัน

## 4. แชร์ แจ้งเตือน และปล่อยทดลอง

1. ทำหน้าทริปบนมือถือให้เห็นการกระทำที่ต้องทำก่อนผลรวม; เพิ่มปุ่มคัดลอกลิงก์และข้อความสรุปทริปสำหรับส่งในแชต
2. บันทึกเหตุการณ์สำคัญและแสดงแจ้งเตือนในเว็บ เช่น ถูกชวน เปิดโหวต ใกล้หมดเวลา ยืนยัน เปลี่ยนแผน และยกเลิก; การเตือนใกล้หมดเวลาแสดงตามเวลาปัจจุบันเมื่อเปิดเว็บ
3. ทดสอบเส้นทาง A → B ตั้งแต่ลิงก์เชิญจน RSVP บนมือถือ พร้อมสิทธิ์ของคนนอก, เวลาหมดโหวต, timezone, ข้อผิดพลาด และการกดซ้ำ
4. Deploy บน Vercel Hobby กับ Supabase Free โดยใช้ URL `.vercel.app`; ตั้ง OAuth redirect และ environment ของ production; ทดสอบอีกครั้งกับสองบัญชีจริง

**ผ่าน MVP เมื่อ:** เพื่อนสองคนจบทริปได้โดยไม่แก้ข้อมูลหลังบ้าน ทุกคนเห็นสถานะล่าสุดตรงกัน และคนนอกอ่านหรือเปลี่ยนข้อมูลทริปไม่ได้

## ข้อจำกัดที่ยอมรับในรุ่นทดลอง

- ใช้ Google login เท่านั้น และไม่มีอีเมล/ข้อความ push อัตโนมัติ; ผู้จัดส่งลิงก์เตือนผ่านแชตเอง
- ไม่รับประกัน uptime ของ free tier; Supabase อาจพักโปรเจกต์ที่ไม่ค่อยมีการใช้งาน
- Vercel Hobby ใช้กับการทดลองส่วนตัวที่ไม่ใช่เชิงพาณิชย์ หากเปลี่ยนเป็นบริการเชิงพาณิชย์ต้องเลือกแผนโฮสต์ที่อนุญาตก่อนเปิดใช้งาน
